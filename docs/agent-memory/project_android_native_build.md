User can build standalone Android APKs to test on a physical phone (confirmed working as of 2026-06-12).

- **Debug APK** (`assembleDebug`) requires the Metro dev server reachable on the same network — on a real phone without Metro, the app gets stuck on the native splash screen. Use this only when iterating with Metro running.
- **Release APK** (`assembleRelease`) bundles the JS via Hermes — fully standalone, no Metro needed. This is the one to hand to the user for phone testing. Output: `android/app/build/outputs/apk/release/app-release.apk`. `android/app/build.gradle`'s `release` buildType reuses `signingConfigs.debug` (debug keystore), so no extra signing setup is needed.

**Gotchas:**
- `android/local.properties` (regenerated by `npx expo prebuild --platform android --clean`, gitignored) must contain `sdk.dir=C:\\Users\\Admin\\AppData\\Local\\Android\\Sdk` with **double backslashes** — single backslashes (e.g. from a bash `echo`) break Java's properties parser (`\U` → invalid unicode escape) and fail the Gradle SDK location check. Recreate with the Write tool after every `prebuild --clean`.
- The `@expo/ui` package was removed (`npm uninstall @expo/ui`) — it was unused in app code but its canary version (`0.2.0-canary-...`) declared `coreFeatures: ["compose"]` and referenced a Compose API class missing from the installed `expo-modules-core`, causing a `NoClassDefFoundError` crash on startup. Don't re-add `@expo/ui` without checking `expo-modules-core` compose support.
- The system-wide `JAVA_HOME` env var points to a non-existent path (`C:\src\jdk-17\jdk-17.0.14+7`), causing `./gradlew assembleRelease` to fail with "JAVA_HOME is set to an invalid directory". The actual installed JDK is at `C:\src\jdk-17\jdk-17.0.18+8`. Always override per-command: `JAVA_HOME="C:\src\jdk-17\jdk-17.0.18+8" ./gradlew assembleRelease`.
- `npx expo prebuild --platform android --clean` can fail with `EBUSY: resource busy or locked, rmdir 'android'` if a Gradle daemon still holds file handles. Fix: `cd android && JAVA_HOME="..." ./gradlew --stop` first. If still EBUSY, drop `--clean` — `npx expo prebuild --platform android` (no clean) regenerates config/icons in place without deleting the directory, and `android/local.properties` survives.
- **Adaptive icon "cropped" bug**: if `android.adaptiveIcon.foregroundImage` points directly at a pre-rendered icon PNG whose visible content (logo + its own rounded-square card + shadow) fills the canvas edge-to-edge, Android's launcher mask (circle or rounded-square depending on device) crops the outer ~33%, cutting off side content. Fix: generate a separate "*_adaptive.png" where the original art is scaled to ~66% and centered on a transparent canvas (e.g. via Python/PIL: resize to 0.66x, paste centered on transparent square), then point `foregroundImage` at that file. Keep the original full-bleed PNG as the top-level `icon` (used for iOS/web) unchanged. `windowsTopath`-resolved temp screenshots (e.g. `/tmp/x.png` from Git Bash) must be read via `C:\Users\Admin\AppData\Local\Temp\x.png` for the Read tool.

**How to apply:** For any future "build/test on phone" request, build `assembleRelease`, not `assembleDebug`. Verify on the local Android emulator (`Medium_Phone_API_36.1`) via adb (install, launch, logcat, screenshot) before handing the APK to the user, since the user's physical phone isn't directly accessible via adb.
